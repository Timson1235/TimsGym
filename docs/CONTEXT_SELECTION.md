# Experimental context selection

Branch: `experiment/context-selection`, based on local `developer`, including
the interrupt/retry and active-workout accordion commit.
Claude uses this prototype when `CLAUDE_CONTEXT_SELECTION=true` (default on this
experimental branch). Set false to restore the baseline. Gemini does not perform
context selection. No new model service, database schema or frontend is required.

Each offered Claude tool accepts an optional `_context` input. The transport
validates and removes it before invoking the existing tool handler. This lets
the current model select the next round's view alongside a useful tool call,
without a dedicated context-planning call:

```json
{
  "workout_id": "selected-workout-id",
  "_context": {
    "history": "recent",
    "results": [
      {"call_id": "previous-tool-use-id", "mode": "summary",
       "summary": "Selected workout X from these candidates."}
    ],
    "tools": ["get_workout_details", "start_workout_session"]
  }
}
```

`history` supports all, recent (four historical messages plus the current user
request), or current. The system instruction, including profile, constraints,
summary and active state, is never removed. Relevant constraints in omitted chat
messages are NOT automatically extracted; selection remains a quality risk.

Only earlier read-only results may be summarized. The request-local original
exchange archive stays intact. Selecting `mode: full` prioritizes exact data
within the read budget; repeating an original read retrieves its cached data
without another database read. Call/result IDs and order remain intact.
Mutation exchanges, including their arguments and outcomes, cannot be compacted.
Model summaries are marked as model notes, not authoritative source evidence.
Context-control inputs are removed from subsequent conversation views.

Tool selection filters already activated capabilities; it cannot activate new
tools or authorize sibling calls. discover_tools stays available and discovered
tools join the next selection. Normal discovery validation, user scoping,
mutation/fallback guards, round limits and interruption still apply. Invalid
context instructions reject the associated tool before execution.

Session browsing guidance now requests lightweight candidates before fetching
one selected workout. Full read feedback replaces legacy cross-result references
in this mode, preventing dangling read-* refs after compaction. Database read
deduplication remains enabled. If Claude falls back to Gemini, that request also
uses full feedback, avoiding references to Claude-only evidence.

Private model spans capture the actual selected payload; round trace steps record
contextCharacters and contextBudget (read characters before/after, limit and
compacted-result count) for comparison. Full original tool output remains in existing
private tool traces. Nothing is persisted as a new cross-request cache.

## Structured evidence fix — November 11, 2026

The old 12,000-character hard cutoff could replace a fresh 16-exercise batch with
only the beginning of its first result. Re-fetching could repeat the same loss.
That behavior is removed. No raw JSON prefixes are sent as evidence.

- Progression results retain every exercise identity, status, reason, target,
  progression configuration, source date/ID, and latest actual performance.
- Supporting historical evidence is omitted with an explicit count. Actual sets
  may use columns/rows to reduce repeated field names; values, unknown effort
  and set types remain intact. Numeric targets are never generated by a summary.
- Every batch item is processed separately. Identical items in regrouped batches
  reference the latest call ID and item key. Raw originals remain in traces and
  the request archive. These are request-local references, not persistent memory.
- Model-written summaries cannot replace progression decisions. Full selection
  still prioritizes other reads; original supporting history can be looked up
  through targeted history/detail tools when needed.
- The 12,000-character value is now a soft target for essential decision evidence.
  Preserve decisions rather than silently dropping exercises. Other old reads
  become explicit omission receipts with targeted retrieval guidance.
  `essentialOverflowCharacters` exposes overflow in context-budget traces.
  This is not a hard token/dollar cap on the entire prompt.
- After two consecutive read rounds add no new structured results, or before
  the fifth ordinary round (leaving one preview correction opportunity), an already activated workout-preview tool becomes
  the only offered tool. The model may create the requested preview or ask for
  essential missing information; no mutation is forced. Activation/validation,
  mutation replay guards, personal constraints and final text-only limits remain.
- `needs_setup` is not a requirement to ask users for every parameter: the coach
  can propose clearly labeled new starting targets, without inventing old plans
  or overriding deterministic holds. Missing essential facts still require a
  focused clarification.

## Research behind the choice

Reviewed November 11, 2026:

- [Anthropic context engineering](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)
  motivates targeted retrieval and maintaining the high-signal context needed
  for the current task. Our adaptation is a deterministic exercise decision view.
- [Context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing)
  distinguishes clearing old tool results from summarization. We retain active
  decisions and remove redundant supporting data rather than discard fresh reads.
- [Compaction overview](https://platform.claude.com/docs/en/build-with-claude/compaction)
  describes server-generated summaries of older conversation turns. We did not
  add another summarizer call to this short planning workflow: exact structured
  exercise fields can be compressed without model-generated numeric facts.

These are design choices informed by the sources, not claims of measured speed
or accuracy improvements from their publications. No vector store, new model,
new persistent memory or automatic private-trace ingestion is introduced.

## Verification

Synthetic regressions exercise a 16-exercise batch larger than the old cutoff,
unknown effort, mixed hold/setup decisions, target preservation, model-note
protection, explicit essential overflow, regrouped repeated batches, mutation
preservation and a preview following repeated reads. They verify model-facing
payloads, not just database results. Existing provider, progression, streaming,
access-control and fallback suites must continue to pass. Live Haiku evaluation
is separately budgeted; failed provider calls are not passing evaluations.

November 11 validation: 182 backend tests pass. A synthetic 16-exercise stress
fixture shrank from 56,039 to 9,247 read-result characters while preserving every
decision and latest set (not a token benchmark). The final live Haiku large-workout
run passed 11 workflow checks, created a 10-exercise preview in five calls, took
27.723 seconds and cost approximately $0.00653. Local ignored report:
`backend/evals/results/20261111-162345-5c69f0/report.json`. It used a $0.03 ceiling,
24k input / 4096 output allowance and up to nine calls. This is not a controlled
comparison with the user's real account/request.

Manual review: synthetic hold loads and unset actuals were preserved. The reply
incorrectly described missing setup as no recorded baseline for one exercise.
Scientific quality and duration estimates were not validated. An earlier live
smoke run also found Haiku guessing a barbell variant for ambiguous logging;
that separate issue remains unresolved. Missing-effort advice held the weight
but overpromised future eligibility. Keep these failures visible. Earlier large
runs hit eval input/call caps; final explicit allowances match production loop
capacity while retaining the dollar ceiling. No deployment has been performed
for this fix yet; automatic approval review requires explicit approval to push
it to production main.
